## 1. Что уже сделано (текущее состояние)

### Архитектура: код владеет форматом, LLM только классифицирует
Малые локальные модели (qwen3.5-9b / gemma-4-E4B) не держат строгий формат
copy-and-edit, поэтому:

- **Код** детерминированно считает: номера тикетов, время, группировку,
  сортировку (по убыванию времени), подытоги по клиенту, формат строк
  `Ticket NNNNN | CUSTOMER | SUBJECT | TIME`.
- **LLM** делает один вызов: получает реальный экранный текст каждой сессии
  и возвращает по строке `ID | CUSTOMER | SUBJECT`. Код мёржит ответ:
  факты из кода (номер тикета, клиент из домена) имеют приоритет, модель
  заполняет пробелы.

### Почему не «весь текст сразу»
- Сырой OCR за день: **350 961 символ ≈ 84 000 токенов**.
- Окно текстовой модели: **32 768 токенов** (`text_model_window()`).
- Даже после дедупликации одинаковых экранов (203 уникальных) — **~84k токенов**,
  т.е. **2.6× окна**. Это физический предел, а не настройка.
- Решение: окно заполняется **бюджетированно** — доля контекста на сессию
  пропорциональна потраченному на неё времени. Раньше модель получала дайджест
  на ~1k токенов (3% окна) — отсюда и «Other work (no ticket)».

### Группировка и клиенты
- НЕТикетная работа группируется **по нормализованному заголовку окна**
  (`_normalize_title`), а не по имени приложения — иначе весь Chrome/Outlook
  сваливался в одну корзину.
- Клиент извлекается детерминированно:
  - домен в заголовке (`Users - engelwoodgroup.com` → ENGELWOODGROUP);
  - ALL-CAPS-токен компании (`INCIDENT REPORT - ATDOMCO ...` → ATDOMCO);
  - email-домен в OCR тикетной страницы.
- Фильтры: инфраструктурные токены (GITSMGMT, DG5017, FSLOGIX, BASTION, XA, MGT)
  не считаются клиентами; шум (лок-скрин, ScreenMind, Mercedes, YouTube) исключается;
  слияние вариантов клиента («OMEA ADVISORS» / «OMEA ADVISORS SARL»).

## 2. Проблемы, которые нужно исправить

### Проблема №1 — заголовки удалённых сессий выдаются за задачи
**Симптом:**
```
— | — | Remote session: GITSMGMT-XA FSlogix | 55 min
— | — | Remote session: DG5017 MGT Desktop Bastion | 30 min
```
**Суть:** это НЕ задачи, а заголовки окон удалённых сессий админа
(Citrix Desktop Viewer). Имя хоста (`GITSMGMT-XA`, `DG5017 MGT Desktop Bastion`) —
это просто название сессии, оно не описывает работу. Сейчас `_preset_subject`
превращает его в псевдо-задачу `Remote session: <host>`.

**Где в коде:** `_preset_subject`, ветка
`if "desktop viewer" in t.lower() or "citrix" in app_low:` →
`return f"Remote session: {m2.group(1).strip()}"`.

**Варианты решения (нужен выбор):**
- **A. Исключить** Citrix/Desktop-Viewer сессии из таймшита полностью
  (это админ-инфраструктура, не биллинг). Время теряется, но вывод чище.
- **B. Пометить как внутреннюю работу** одной строкой без выдумки:
  `— | GITS | Remote administration (Citrix) | 1:25 h` — без имени хоста как «задачи».
- **C. Искать настоящую задачу в OCR** содержимого удалённого экрана:
  передать текст сессии в LLM и спросить «что делали внутри». Если OCR пуст —
  fallback на вариант B.

Рекомендация: **C с fallback на B** (не выдумывать задачу из имени хоста).

---

### Проблема №2 — составной заголовок окна склеивает разные задачи
**Симптом:** окно `SplunkInstall.ps1 - Sharepoint Permissions - Visual Studio Code`.
**Суть:** это одно окно редактора, но внутри — **две разные задачи**:
скрипт `SplunkInstall.ps1` и проект `Sharepoint Permissions`. Текущая группировка
по целому заголовку считает их одной работой.

**Где в коде:** `_aggregate_timesheet`, ключ `key = _normalize_title(title)[:80]`
для нетикетных окон — весь заголовок целиком становится одной сессией.

**Почему сложно:** заголовок редактора имеет вид
`<активный файл> - <папка/проект> - <приложение>`. Без анализа содержимого
нельзя достоверно понять, какая доля времени относится к файлу, а какая к проекту.

**Варианты решения:**
- **A. Для окон редакторов брать именем документа/файла** как первичный subject
  (первый сегмент до ` - `), а не всем заголовком. Это честнее: активный файл —
  и есть текущая задача.
- **B. LLM-разделение:** передать заголовок + OCR и попросить модель выделить
  логические задачи. Ненадёжно на малых моделях, но дает шанс разделить.
- **C. Оставить как есть**, но в subject выводить только имя файла
  (`SplunkInstall.ps1`), не смешивая с именем проекта.

Рекомендация: **A** (детерминированно, честно, без галлюцинаций);
B — как опциональное улучшение позже.

### Проблема №3 — клиент без названия задачи
**Симптом:**
```
ENGELWOODGROUP
— | ENGELWOODGROUP | — | 10 min
Subtotal: 10 min
```
**Суть:** клиент извлечён (из `Users - engelwoodgroup.com`), но subject пуст.
Строка «клиент есть, задачи нет» бесполезна.

**Где в коде:** `_run_timesheet_mode`, ветка `else:` —
`subject = preset if preset and preset != "—" else (_clean(m_subj) or "—")`.
Если и `_preset_subject` пуст, и LLM вернул `—`, получается `—`.

**Варианты решения:**
- **A. Fallback на заголовок/имя документа:** если subject пуст, взять
  нормализованный фрагмент заголовка окна (или имя файла) как subject.
  Гарантирует непустую строку.
- **B. Повторный targeted-вызов LLM:** для сессий с пустым subject сделать
  второй короткий запрос только по их тексту. Дороже, но точнее.
- **C. Скрывать строки без subject**, уводя их в «прочее» — но это возвращает
  старую проблему «Other work».

Рекомендация: **A** (детерминированный fallback), при желании поверх — **B**.

## 3. Драфт-план реализации (по шагам)

> Порядок выбран так, чтобы каждый шаг давал проверяемый результат и не ломал
> текущий зелёный вывод.

1. **Шаг 1 — Проблема №3 (самая простая, чинит «пустой subject»).**
   - В `_run_timesheet_mode` добавить fallback: если subject пуст —
     использовать `_fallback_subject(entry)` = имя документа / очищенный
     нормализованный заголовок (без имени приложения и служебных суффиксов).
   - Убедиться, что строка никогда не выходит с subject `—`, если есть заголовок.
   - Проверка: в выводе нет `| — | <time>` для нетикетных строк с известным клиентом.

2. **Шаг 2 — Проблема №1 (удалённые сессии).**
   - В `_preset_subject`/агрегации пометить Citrix/Desktop-Viewer окна как
     `kind="remote"`. Не генерировать из имени хоста «задачу».
   - Реализовать вариант **C→B**: передать OCR сессии в LLM для поиска реальной
     задачи; если пусто — свернуть в одну строку
     `— | GITS | Remote administration (Citrix) | <суммарное время>`.
   - Решение об исключении vs внутренней строке — подтвердить у пользователя.

3. **Шаг 3 — Проблема №2 (составные заголовки редакторов).**
   - Детектор окон редакторов (VS Code / Word / Excel / ISE и т.п.).
   - Для них subject = первый сегмент заголовка (активный файл/документ),
     а не весь заголовок. Группировку оставить по окну, но subject честнее.
   - Опционально: LLM-разделение на подзадачи (отложить).

4. **Шаг 4 — Регресс и деплой.**
   - Прогнать `./.venv-test/Scripts/python.exe -m pytest -q` (ожидание 536 passed).
   - Прогнать агента end-to-end на реальных данных, сверить вывод.
   - Задеплоить `agent_runner.py` в установленный пакет, перезапустить сервер,
     пересобрать `dist_build/timesheet-agent.zip`.

## 4. Открытые вопросы к пользователю

1. **Удалённые сессии (№1):** исключить из таймшита, показать одной строкой
   «Remote administration», или пытаться вытащить задачу из OCR?
2. **Составные окна (№2):** достаточно ли брать имя активного файла как задачу,
   или нужно именно разделять время между файлом и проектом?
3. **Пустой subject (№3):** приемлем ли fallback на имя документа/заголовок,
   или нужен повторный LLM-запрос ценой времени?
